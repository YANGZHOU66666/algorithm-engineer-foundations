## GRPO训练MOE模型会遇到什么问题？

MoE+Off-Policy=不稳定：有时就算正在训练的模型和采样模型的参数差不多，但就因为一点的差距导致激活了不同的专家，ratio差距很大，很不稳定。

解决方法：

- Routing Replay

缓存$\pi_{old}$推理时激活的专家，在计算$\pi_\theta(y_{i,t}|x_i,y_{<t})$推理时进行“重放”，也激活相同的专家

不足：额外的存储和通信开销

- GSPO

ratio按sequence likelihood来算。由于MoE模型仍然保持语言建模能力，所以sequence likelihood波动不会很大

## Decoder-Only模型为什么成为主流？

算法层面：

- 注意力满秩问题：Encoder层由于每个词都关注双向上下文，很可能每个词都只关注几个特定的核心词，导致注意力得分的矩阵变成低秩矩阵，信息效率不高；而Encoder-Decoder由于加了下三角矩阵的Mask，导致注意力得分一定是一个下三角矩阵，一定是满秩矩阵

## 复读机问题怎么解决

训练时：

- 数据：使用不要有太多重复的、更多样性的数据
- 重复自注意力掩码：训练时通过掩码降低模型对重复词的注意力
- 强化学习的策略：在奖励函数处额外引入重复的惩罚

推理时：

- 随机采样：不要使用贪心解码。而是使用：

  - sampling decoder，且可以适当调高temperature
  - top-k，top-p适当调高
  - beam search，代价是速度慢+生成的文本会比较保守和固定

- 重复惩罚：在生成的时候，对已经生成过的token的logits额外除以一个参数$\theta$$(\theta>0)$

  $ p_i = \frac{\exp \left( x_i (T \cdot I(i \in g)) \right)}{\sum_j \exp \left( x_j (T \cdot I(j \in g)) \right)}, \quad I(c) = \theta \ \text{if} \ c \ \text{is True else} \ 1 $

## 灾难性遗忘是什么？怎么解决？

灾难性遗忘：当一个已经训练好的神经网络模型去学习一个新的任务时，它在学习新知识的过程中，会**突然、显著地忘记**之前已经学好的旧知识。这种对旧知识的遗忘不是渐进的、轻微的，而是“灾难性”的，可能导致模型在旧任务上的性能急剧下降，甚至完全失效。

解决方法：

1. 正则化方法

- 弹性权重巩固 (Elastic Weight Consolidation, EWC)

  公式：$$ L(\theta) = L_B(\theta) + \sum_{i} \frac{\lambda}{2} F_i (\theta_i - \theta_{A,i}^*)^2 $$，$L_B(\theta)$ 是新任务B的损失。 第二项是正则化项，其中 $\lambda$ 是超参数，$F_i$ 是权重 $i$ 对旧任务A的重要性，$\theta_{A,i}^*$ 是旧任务训练好的权重。

2. 回放/重放方法：

- 经验回放：事先存储好以前任务的数据
- 生成式回放：训练一个生成模型来学习旧任务的数据分布。在学习新任务时，利用这个生成模型“凭空创造”出一些伪旧样本来进行回放训练

3. 基于参数隔离/动态架构的方法：

- MoE网络：训练一组“专家”子网络，并用一个“门控”网络来决定在处理特定输入时应该使用哪个或哪些专家
- 路径网络：在一个巨大的、固定的网络中，为每个新任务寻找一个特定的“路径”（即一部分激活的神经元和权重）。在训练新任务时，只更新该任务路径上的权重，而冻结网络中的其他部分。



## GRPO为什么要做归一化

1. 降低多个rollout间奖励的方差，稳定强化学习训练（举例：有的样本100分，有的1分，有的0分。那么不归一化的话梯度差距会特别大，训练不稳定）
2. 提供相对评价，使能面向较好样本、远离较差样本的方向优化。否则对于全正样本都会优化，全负样本都会削弱

## Reward Hacking是什么、怎么识别、如何解决（20260518阿里巴巴控股集团一面）

是什么：RL训练时LLM为刷高奖励分可能产生投机行为，实际回答效果没有变好

示例：问答LLM输出大量讨好重复文本、Agent假装工具调用实际没调、Code Agent改测试用例而不是生成正确代码等

识别：

1. 奖励分数持续上升，真实任务质量没有提升或下降。代理奖励（训练信号）↑  +  真实指标（人工评估）↓  →  Hacking 信号。说明模型在优化proxy，而不是真实目标。

   具体的，可以定性分析（人工观察训练中推理结果）、评测指标（训练中/后的模型评估指标）

2. 熵坍缩：出现重复或固定范式的回答；KL骤升：和原始分布相距太远

3. 高级技巧，对抗性测试和干预。训练一个二分类模型，用于分类”模型生成的样本“和”真实数据（或人认可的样本）”。若能明显分类，说明LLM输出的内容和真实数据分布有偏差

解决：

1. 约束型：调高KL散度系数。避免LLM在奖励模型盲区里过度外推、采取极端行为
2. 最核心的方法：优化给奖励的全面性，减少能钻空子的地方
   - 不要优化单一指标，多设置一些细粒度的指标，减少能钻空子的地方；或者多个奖励模型作评审团
   - 规则型指标相对RM更不容易钻空子一些（如数学题对就是对，回复重复了就是重复了）
   - 如果是奖励模型，可以根据出现reward hacking的case多补充一些正负样本，尽可能覆盖全面“差“样本

## LLM as a Judge实践需要考虑哪些点？（20260521拼多多广告算法一面）

1. 模型偏见：

长度（解决：prompt中强调长度无关）、位置（解决：交换顺序取平均）、偏好同模型（用不同模型）等

2. 一致性和可靠性

temperature = 0；多次采样投票、多模型judge等

3. Prompt（也即评估标准）的设计

尽可能对每个指标维度描述准确、打分粒度更细（避免全部集中在一起拉不开差距）；每种打分添加合适Few-Shot；添加合适的COT

4. 模型选择

强于生成样本的模型；尽可能足够强，保证足够遵循评估要求；不要和被测模型同源
