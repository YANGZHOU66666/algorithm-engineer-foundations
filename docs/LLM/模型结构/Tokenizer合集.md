# Tokenizer

## word粒度 vs 字符粒度 vs subword粒度

- 词（word）粒度：

优点：词的边界和含义得到保留

缺点：长尾效应大，包含大量稀有词，稀有词很难学好；OOV（out of vocabulary）问题；无法处理同一个单词的不同形态问题和词缀关系

- 字符粒度：

优点：词表很小

缺点：无法承载丰富语义；序列太长，加大计算资源

- 子词（subword）粒度：

优点：平衡词表大小与语义表达能力，也能解决OOV问题



## BPE

**算法流程：**

1. 将大量无监督语料预分词，转换为“词-词频统计”的格式
2. 先将所有字符和标点作为初始词表
3. 在词表所有词中的二元组中找频率最大的，作为要合并的词，将这个二元组放入词表
4. 重复3的过程，直到词表大小达到设定的值

**举例：**

假设原始语料库长这样：

```
low low lowest newer newer wider low newer wider lowest low low newer wider newer newer
```

而我们打算建一个长度为15的词汇表。

第一步：预分词。将每个词提出来，并且在每个词后面加上一个特殊字符\</w>表示词的结束

```
low</w>       (5次)
lowest</w>    (2次)
newer</w>      (6次)
wider</w>      (3次)
```

初始词表如下：

```
l, o, w, e, s, t, n, r, d, i, </w>
```

第二步：统计词表中两两结合的产物中，词频最高的。这里最高频的组合是`er`，出现了9次

于是，语料库变为：

```
l o w </w>         (5次)
l o w e s t </w>     (2次)
n e w er </w>       (6次)
w i d er </w>       (3次)
```

词表变为：

```
l, o, w, e, s, t, n, r, d, i, </w>, er
```

第三步：继续迭代统计词表中两两结合的产物中，词频最高的。这里最高频的组合是`er</w>`，出现了9次。

于是，语料库变为：

```
l o w </w>         (5次)
l o w e s t </w>     (2次)
n e w er</w>       (6次)
w i d er</w>       (3次)
```

词表变为：

```
l, o, w, e, s, t, n, r, d, i, </w>, er, er</w>
```

以此类推。



**具体对新的文本分词时：**也是先预分词为单词。然后贪心合并，即对当下，有最长的就选最长的

例如，对于单词`lowest</w>`，先给拆成字符级：`l o w e s t </w>`

先检查到发现对于这个单词开头，词表中能最长的就是low，那么变成`low e s t </w>`

然后开始尝试从e开始合并，这里假如发现词表中es和est都没有，那么e只好单独

再尝试从s开始，以此类推。



## BBPE

BPE的改良版，以字节为单位构建基础词表，而不是字符。【区别：就是说初始词表大小就是256，而BPE在有汉字或其他非英文文字的场景下，由于汉字是unicode编码，一个字可能有多个字节组成，因此BPE初始词表就是所有的汉字（占多个字节），而非字节】
